# Договори: підпис і КЕП

## Що працює зараз (без жодних реєстрацій)

1. **Підпис і печатка** (зображення з «Реквізитів», як в актах): кнопка «Підписати печаткою» → сервер (`/api/contracts/sign`, `method: image`) малює їх на останній сторінці скану й кладе `signed-<uuid>.pdf` у приватний бакет. Потрібні права «Договори» і «Підпис і печатка»; директору йде сповіщення, якщо підписав логіст.
2. **КЕП через id.gov.ua/sign** (усі типи ключів — див. нижче): кнопка «Підписати КЕП» показує три кроки: зберегти скан → підписати файл на [id.gov.ua/sign](https://id.gov.ua/sign) **окремим файлом підпису (.p7s, CAdES)** → завантажити .p7s. Сервер перевіряє ФОРМАТ (DER, signedData), зберігає `.p7s` поруч зі сканом і ставить статус «підписано».

Сервер **не перевіряє криптографію** підпису (ланцюг сертифікатів, строк дії, відповідність файлу): це робить ЦСК / id.gov.ua. Якщо потрібна перевірка на нашому боці — окрема задача (бібліотека ІІТ або сервіс перевірки).

## Що відомо про id.gov.ua (перевірено на сторінці https://id.gov.ua/)

- Сервіс підпису розміщений на `id.gov.ua/sign`; файл «оброблюється у браузері та не передається на сторону id.gov.ua».
- Типи ключів, які перелічені на сторінці: **файловий ключ** (Key-6.dat + пароль), **токен**, **хмарний ключ**, **Дія.Підпис** (активація в застосунку Дія, QR-код і перевірка обличчя); також ID-картка й BankID НБУ для автентифікації.
- Сторінка описує **ICEI** (автентифікація користувачів у ваших системах): приєднуються лише надавачі електронних послуг, документи подаються з КЕП, токен доступу видається на домен і `redirect_uri`.
- **Вбудовуваного віджета підпису для сторонніх сайтів на цій сторінці немає**, документації його протоколу (postMessage / параметри) я не знайшов. Тому віджет у коді — лише каркас (`src/lib/kep-widget.js`): протокол не вигадано.
- Чи віддає `id.gov.ua/sign` саме відокремлений CAdES `.p7s` і чи підтримує Дія.Підпис цей режим, потрібно перевірити вручну одним підписанням (у налаштуваннях підпису обрати «окремий файл підпису»).

## Що зробити вам, щоб підключити віджет (якщо він існує для вашого випадку)

1. Звернутися до ІІТ (iit.com.ua) / служби підтримки id.gov.ua: чи надається вбудований віджет підпису для сторонніх сайтів, умови підключення, документація протоколу, домени для CORS / `frame-src`.
2. Отримати від них: URL віджета, вимоги до реєстрації вашого домену (`app.trip-control.com`), опис обміну повідомленнями.
3. Vercel (проєкт Контроль+): додати `KEP_WIDGET_URL` = `https://…` (лише https). Тоді `GET /api/contracts/sign` віддасть `kep.widget_url`, а в картці договору з'явиться кнопка «Підписати у віджеті».
4. У `apps/kontrol-plus/vercel.json` додати origin віджета в `frame-src` (зараз `'none'`) і, якщо треба, в `connect-src`.
5. Реалізувати `openKepWidget` у `src/lib/kep-widget.js` за їхнім протоколом: на вхід байти файлу договору, на вихід байти `.p7s`. Далі потік той самий: завантаження `sig-<uuid>.p7s` і `POST /api/contracts/sign { method: 'kep' }`.

## Дані

Бакет `kp-contracts` приватний, 10 МБ. Шлях `<org_id>/<contract_id>/<scan|sig|signed>-<uuid>.<ext>`. Читання лише для учасників своєї організації (RLS на `storage.objects` за `org_id` у шляху); посилання — підписані URL на 10 хвилин. Скан і `.p7s` завантажує клієнт (за правами), підписану копію пише лише сервер.

## Перевірка файлів на сервері

- Скан додається через `POST /api/contracts/sign { method: 'scan' }`: сервер визначає організацію користувача (RPC `kp_contract_scan_context`, право «Договори»), звіряє її з шляхом файлу ДО читання службовою роллю, перевіряє розмір і **справжній тип за magic bytes** (PDF `%PDF-`, JPG `FF D8 FF`, PNG-сигнатура) на відповідність розширенню; інакше 415 `BAD_FILE_TYPE` і файл видаляється з бакета.
- Те саме для `.p7s`: організація зі шляху звіряється з організацією користувача до читання; формат DER signedData перевіряється як і раніше.
- Підпис печаткою й відправка листом повторно перевіряють тип за magic bytes. MIME бакета: лише `application/pdf`, `image/jpeg`, `image/png`, `application/pkcs7-signature` (без `application/octet-stream`); повторне застосування міграції повертає бакету приватність і ліміти.
- `kp_contract_attach` і `kp_contract_attach_sig` — лише для `service_role` (із клієнта не викликаються). API кличе їх після перевірки magic bytes з `p_actor` = користувач із перевіреного JWT; всередині: членство в організації договору (`kp_is_org_member`, та сама логіка, що `kp_org_id`), право «Договори» (для `.p7s` ще «Підпис і печатка») через `kp_actor_can`, статус чернетки. Директор лише читає.
