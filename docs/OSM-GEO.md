# Адреси й відстань за OpenStreetMap (лендинг і демо)

Гість на лендингу (панель «Спробувати розрахунок») і демо-акаунт у застосунку отримують підказки адрес і відстань
за дорогами з OpenStreetMap. Платні / схвалені акаунти й далі працюють з Google ([GOOGLE-MAPS-API-KEY.md](GOOGLE-MAPS-API-KEY.md)).
Пошук об’єктів уздовж маршруту (Overpass, `POST /api/poi`) ці режими не чіпають: він, як і раніше, лише для схвалених.

## Ендпоінт

Без нової функції — гілка на початку `api/poi.js` (`handleGeo`). Анонімно, без Bearer: лендинг працює без входу.
Браузер ходить лише на наш `/api/poi`, ніколи напряму на Photon / OSRM (CSP `connect-src 'self'` не змінювали).

| Запит | Відповідь 200 |
|---|---|
| `GET /api/poi?mode=geocode&q=житомир` — `q` 3–100 символів | `{ items: [{ label, name, city, region, lat, lon }], source: 'photon', attribution }` — до 6 підказок, `label` = «Назва, місто/громада, область[, країна]» |
| `GET /api/poi?mode=route&from=lat,lon&to=lat,lon[&base=lat,lon]` | `{ km, podacha_km?, source: 'osrm', estimate: true, attribution }` — `km` для A→B, `podacha_km` для base→A |

Помилки — короткий JSON `{ code, error }` українською, без стеків:
`GEO_BAD_INPUT` 400, `GEO_NO_ROUTE` 404, `GEO_RATE_LIMIT` 429, `GEO_UNAVAILABLE` 502, `GEO_TIMEOUT` 504.
Координати перевіряються (числа, межі Європи: lat 34…72, lon −25…60) і округлюються до 4 знаків; `q` — trim + нижній регістр.
Клієнт (`assets/osm-geo.js`) нормалізує так само, щоб однакові запити мали однаковий URL.

## Джерела

- Підказки: Photon `https://photon.komoot.io/api/?q=…&limit=6&lat=49.0&lon=31.5` — зсув до центру України без bbox,
  щоб лишались адреси в ЄС. Публічний Photon підтримує лише `lang=default|en|de|fr`; беремо `default` (місцеві назви, для України — українською).
  Точки поза межами Європи відкидаємо.
- Відстань: публічний demo-сервер OSRM `https://router.project-osrm.org/route/v1/driving/…?overview=false&alternatives=false&steps=false`.
- Заголовки: `User-Agent: trip-control.com (support@trip-control.com)` (той самий, що для Overpass), `Referer: https://trip-control.com/`.
- Таймаут 7 с на запит (`AbortController`), без повторів.

## Захист і кеш

- **Rate limit на IP** (перший елемент `x-forwarded-for`, запасний — `x-real-ip`): geocode 60/хв, route 20/хв, однаково для гостей і демо.
  Лічильник — у пам’яті інстансу функції (Map з обрізанням до 5000 ключів). Він **м’який**: скидається на холодному старті,
  різні інстанси не діляться лічильником. Для старту цього досить; постійний ліміт потребує таблиці (окрема міграція — лише за погодженням).
- **Бюджет на upstream**: окремі бакети для Photon і OSRM на інстанс (≈1 запит/с, запас до 4). Понад бюджет —
  `GEO_RATE_LIMIT` без запиту до сервісу; некоректні запити (у т. ч. route з невалідним `base`) бюджет не витрачають.
  Клієнт на `GEO_RATE_LIMIT` для route робить один повтор приблизно за секунду, далі — ручне введення км.
- **CDN Vercel**: успішні відповіді — `Cache-Control: public, s-maxage=604800` (geocode) і
  `public, s-maxage=86400, stale-while-revalidate=604800` (route). Повтори того самого URL віддає CDN без виклику функції
  і без запитів до Photon / OSRM. Помилки — `no-store`.
- Таблицю `poi_cache` не використовуємо (у неї CHECK на типи POI і короткі ключі); міграцій немає.

## Точність

OSRM рахує за профілем **легкового авто** (`driving`), без вантажних обмежень (мости, вага, заборони для TIR), тож це **оцінка**.
Поле «Відстань» / «Подача» лишається редагованим; ручне значення не перезаписується мовчки — перерахунок лише після нового
вибору точки або A↔B. Під полями — «Відстань за OpenStreetMap, можна виправити» і атрибуція «© OpenStreetMap contributors».

## Вимикач

`var OSM_GEO = true;` у `assets/osm-geo.js` — одне місце для лендингу й демо. `false` прибирає підказки й автовідстань:
поля адрес лишаються звичайним текстом, км вводяться вручну, як раніше. Будь-яка помилка / таймаут / 429 дає ту саму поведінку з підказкою
«Не вдалося визначити відстань — введи вручну, км».

## Обмеження публічних сервісів і план Б

Публічні Photon і OSRM demo мають fair-use правила: OSRM demo — приблизно 1 запит/с, не для великого навантаження і без гарантій.
CDN-кеш і ліміт на IP знижують навантаження, але при зростанні трафіку план Б — власний інстанс Photon / OSRM (або Valhalla з профілем вантажівки)
чи платний провайдер геокодування й маршрутів. Перехід — зміна `OSM_GEO_PHOTON` / `OSM_GEO_OSRM` в `api/poi.js`, клієнт не змінюється.
