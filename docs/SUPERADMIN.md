# Кабінет суперадміна платформи (`#/superadmin`)

Суперадмін — не роль організації, а окрема сутність платформи: рядок у `platform_admins`. Функція `is_platform_superadmin()` (не `is_platform_admin()`: така вже є на сайті для `profiles.role = 'admin'`) повертає, чи поточний користувач у цій таблиці.

## Як додати суперадміна

Лише вручну в SQL-редакторі (UI, API й RPC для цього немає; міграція нікого не додає):

```sql
INSERT INTO public.platform_admins (user_id)
SELECT id FROM auth.users WHERE email = '<пошта адміністратора>';
-- прибрати: DELETE FROM public.platform_admins WHERE user_id = '<uuid>';
```

## Що вміє кабінет

- **Глобальні функції** — рядки `app_settings`. Немає рядка = модуль вимкнений (це показано явно, є кнопка «Створити рядок» — створює вимкненим). Перемикач → `sa_set_setting`.
- **Організації** — пошук за назвою або ЄДРПОУ, кількість активних користувачів, прапорці `organizations.features` (зараз `own_fleet`) → `sa_set_org_feature`. Якщо в компанії увімкнено, а глобально ні, показується «Не працює, бо вимкнено глобально».
- **Аудит** — `platform_audit_log`: хто, коли, що, було → стало; по 50 записів.

Кожна зміна питає підтвердження (діалог сайту) і пише рядок в аудит. Інших дій немає: ні видалення компаній, ні змін користувачів, ні перегляду їхніх даних.

## Безпека

Усі перевірки на сервері: кожна `sa_*` функція (`SECURITY DEFINER`) першим рядком перевіряє `is_platform_superadmin()` і інакше відповідає `42501`; `anon` доступу не має; таблиці `platform_admins` і `platform_audit_log` клієнтам закриті. Фронт лише ховає пункт меню «Платформа», а `#/superadmin` для не-суперадміна веде на огляд. Модулі, які можна створити в `app_settings` з кабінету, перелічені у `sa_create_setting` (зараз `own_fleet`); новий модуль додається і там, і в `src/lib/superadmin.js`.

Міграція `20261123090000_superadmin.sql` лише використовує `app_settings` і `feature_enabled` з #129 (додає колонку `updated_by` і рядок `own_fleet = false`, якщо його ще немає) і застосовується вручну після перегляду.
